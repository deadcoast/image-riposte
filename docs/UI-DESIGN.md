# RIPOSTE workbench — implemented visual direction

The selected [Sauce Labs Uizze reference](https://uizze.com/packs/d271a6c4-942f-4abf-a3de-66795f15f031) informed the hierarchy: a continuous dark surface, selective mint emphasis, monospaced identity, a connected process and unboxed counters. It is a marketing reference, not a template copied into the application. No Sauce Labs screenshot, brand asset, illustration or third-party font file is bundled as application material.

RIPOSTE applies that direction to real artwork inspection. Peripheral surfaces carry a restrained dark green; the raster stage is neutral charcoal. The original R/slash wordmark is typographic UI, not an image watermark. The title, compact counters, one clear primary action and narrow collection tree establish hierarchy without repeated dashboard cards.

## Implemented interactions

The collection is the actual year/month/resolution tree, ordered chronologically in the UI and filtered without empty nodes. A contact-sheet selection opens the same asset in the lab; selection survives view changes. Library search/sort/filter and keyboard-focus states have actual event handlers.

The inspector has a keyboard-accessible comparison slider, clean/candidate/difference modes, fit/native zoom, synchronized panning and clickable real transport views. The lab keeps build parameters, controlled challenge and explicit unverified export adjacent to the image rather than splitting them into unrelated screens.

The connected Clean → Organize → Guard → Challenge → Export strip opens the relevant real operation. Last audit, organized master count and candidates have distinct semantics. No green styling manufactures an AI-protection result. Unknown evaluation protocols and synthetic fixtures are visibly identified.

Five-arm generation review displays the clean baseline prominently, then the candidate and three controls, with shared seed/view and frame controls. Comparisons concern the same frame index. The interface separates pipeline filtering from model disruption and displays human-review requirements.

## Failure and accessibility behavior

Core organizer controls distinguish preview from source-removing apply; only the destructive action receives explicit warning treatment and confirmation. Async model tasks show progress and cooperative cancellation. Missing dependencies or unsupported local model files produce actionable code-only errors rather than a fake render.

Responsive checks cover desktop 1512 px, intermediate 1024 px and narrow 390 px widths. Navigation, lab and tables reflow without page-level horizontal overflow. The comparison control, filters, buttons, modal confirmation and frame slider are keyboard operable. This is functional accessibility work, not a claim of a completed external WCAG audit.

No external font, analytics, image service or remote script is loaded. Screenshots in `evidence/` are actual Chromium renders with original synthetic illustrations and labeled test-double results. See `VALIDATION.md` for the in-process browser transport and separate live-HTTP boundary.

## Next visual refinements

Prioritize inspection of real high-resolution line art, pointer/stylus behavior on native Windows, long-running GPU jobs and genuine multi-frame outputs. Batch selection/protection queues and persisted review notes are not yet implemented. Do not bury failures to make the status surface appear cleaner, and do not sacrifice raster area to decorative lifecycle graphics.
